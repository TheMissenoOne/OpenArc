## OpenArc findings (with repro steps)

1. **A symlinked `node_modules` breaks the example sandbox, and the failure is misreported as example failures that burn every model attempt.** The sandbox mounts only the project at `/work` (`dist/src/sandbox.js`: `--ro-bind <stage> /work`), so a `node_modules` symlink to a directory outside the project dangles. That covers pnpm-style layouts and a shared install. Repro (0.6.2, sandbox code unchanged in 0.6.3/0.6.4): `mkdir shared && cd shared && npm i <open-arc tgz>`; `mkdir ../p && cd ../p && npm init -y && npm pkg set type=module && ln -s ../shared/node_modules node_modules && npx openarc init`; add the README's `normalizeTitleSpec`; `npx openarc scaffold && npx openarc compile`. Expected: one environment error before any model call. Actual: every stderr line of `ERR_MODULE_NOT_FOUND: Cannot find package 'open-arc' imported from /work/.openarc/harness.mjs` becomes its own `OARC-E090 example "<unparseable>" failed: got "<line>"; expected null`, all 3 attempts call the model, then E082. The bench works around it with a hard-linked copy (`cp -al`).
2. **A recursive type alias in `F` makes the spec itself fail with TS2589, and compile charges it to the model.** Repro (0.6.4, tsc only): `export type Nested = Array<number | null | undefined | Nested>; type Flatten = (input: Nested) => number[]; arc.defineRegion<Flatten>({ id: "f.flatten", intent: "...", examples: [{ args: [[1, [2, [3]]]], expected: [1, 2, 3] }] })`, then `npx tsc -p .` gives `TS2589: Type instantiation is excessively deep and possibly infinite` on the `args` line. `openarc compile` reports it as `OARC-E070` on every generated body and spends all attempts; no body can pass. Expected: a spec error (no model call). `interface Nested extends Array<number | null | undefined | Nested> {}` works and is what the bench uses.
3. **No token accounting.** Provenance and `.openarc/attempts/*.json` record model, level, prompt hash and sampling, but not `prompt_eval_count`/`eval_count`/`usage`. "Implementations per unit of compute" (the README's stated hypothesis) can't be measured from OpenArc's own records; the bench proxies the backend to count them.
4. **Examples can't express "throws".** The spec has no `throws` form, so error behaviour (binary-search not found, wordy's errors, VLQ incomplete input) is never verified or shown to the model as an example. In ts-bench v1 that leaves 5 of 11 binary-search tests and about 8 of 23 wordy tests unconstrainable.
5. **Region isolation blocks reuse of a failed sibling.** Pending regions are left out of the context package, so when `foodChain.verse` fails, `foodChain.verses` can't call it and must re-derive the whole song; the baseline writes both in one file and reuses `verse`. This is by design, but it compounds: one failure makes the sibling harder.
6. **Output format is a confound.** Every OpenArc call asks for `{"body": string, "imports": [...]}` under a JSON schema (Ollama `format`, OpenAI `json_schema`); the baseline gets free-form markdown. With 7-9B models, writing code as an escaped JSON string under grammar-constrained decoding may cost accuracy on its own. Untested here; it's the obvious ablation.
7. **L1 equals L0 on single-file tasks.** Exercism exercises import nothing, so A and B produced byte-identical prompts and results; ts-bench v1 can't measure dependency-aware context. C (L2) roughly doubles prompt tokens and didn't help.
8. **Half of a standard TS benchmark doesn't fit the region model.** 13 of 25 ts-bench v1 exercises are classes or stateful APIs and were skipped (reasons in `exercises.json`).
9. **Minor:** OARC-W044 (thin examples) fires on nearly every region under a 3-public-example budget; it's accurate, but it's noise in a benchmark log.

## Next benchmarks, with adapter sketches

- **ContextBench** (repo-level context retrieval for code tasks). It is where L1 should finally matter. Adapter: for each task, take the target function in its repo, run `openarc extract <file> --function <name>` to get a developer-owned region with a checker-derived `type <Name>Fn`, `openarc release` it, blank the body to `arc.todo`, and add the task's tests as examples where they are single calls with JSON values (the same recording trick as `lib/run-tests.mjs --record`, with a shim for the task's test runner). Score: (a) the task's own tests, and (b) context recall, comparing the symbols in OpenArc's L0/L1 package (log the rendered package; it isn't persisted today) against ContextBench's gold context. Baseline: the benchmark's own retrieval setting with the same model. Caveat from this run: tasks whose functions throw or touch I/O need fakes (`defineFake`), so filter to pure functions first and record the share.
- **CrossCodeEval** (TS split; cross-file completion). Closest fit to L1: the gold completion depends on symbols from other files. Adapter: map each sample's completion point to a block region only when the cursor is at a statement boundary inside a function (`defineBlock` + `arc.pending`), otherwise to a function region when the whole body is the target; the import graph comes from the repo snapshot, so L1 gets real cross-file signatures. CrossCodeEval has no tests, so score with its own exact match / edit similarity on the generated block, plus "type-checks" (OpenArc's guarantee) as a second metric; compare L0 vs L1 vs the benchmark's retrieval baselines with the same local model. Expect many samples to be expression completions that don't map to a region: count and report them as a coverage finding.
- **Inspect AI integration.** Wraps this harness so runs are reproducible and comparable with other evals. Sketch: an Inspect `Task` whose dataset is `splits/<exercise>.json` (one `Sample` per exercise, metadata = typed stub, public examples, held-out names); a custom solver that writes the OpenArc project (reuse `specSource`/`configFor`) and shells out to `openarc compile` in Inspect's sandbox (docker with bwrap available, or a local sandbox with the hard-link workaround from finding 1), plus a second solver for the whole-file baseline through Inspect's model API pointed at the same OpenAI-compatible server; a scorer that runs `lib/run-tests.mjs` on the held-out tests and returns passed/total, and `allPass` as the headline. Inspect's per-sample token usage comes for free on the baseline; for OpenArc, keep the counting proxy (finding 3) or add usage to provenance upstream.
