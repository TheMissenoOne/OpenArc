## What happened

- **flatten-array is an OpenArc bug, not a model failure.** The pilot used `type Nested = Array<number | null | undefined | Nested>`. With that type, OpenArc's `Example<F>` type fails with TS2589 ("Type instantiation is excessively deep") on the spec's own `args` line, before any body exists. `openarc compile` charges that error to every generated body, so the region can't pass whatever the model writes, and it spends all 3 calls. The equivalent `interface Nested extends Array<...> {}` type-checks, and the full run uses it. See the full run's summary, finding 2.
- **The rest are genuine model failures,** checked by reading `.openarc/attempts`: acronym turns "HyperText" into "HML" (camelCase not split), wordy's loop advances by one token instead of two, relative-distance treats the tree as directed (siblings come out -1), and food-chain gets lyrics wrong. D failed the same public examples on acronym and relative-distance.
- **A and B are identical** (same tokens, same bodies). A single-file exercise with no imports has no dependency context, so L1 adds nothing. C (L2) doubles the prompt and didn't help.
- **D's held-out score is partly ungated.** On acronym and food-chain, D failed its public examples but shipped its last file anyway, and that file passed most held-out tests. OpenArc ships nothing for a failed region (by design), so it scores 0. Gated the same way, D drops from 2/5 to 1/5 exercises on both models.

## Verdict on the pilot

n = 5 exercises per cell, so this is a smoke test, not evidence. On it the hypothesis is **not supported**: OpenArc verified 0 of 25 (exercise, config) cells at any context level, while the whole-file baseline verified 2 of 5 on the same model with fewer tokens. See `../2026-10-31-untuned-ollama-full-partial/summary.md` (paused after 4 tasks; the full benchmark restarts on the tuned backend) for the 12-exercise run and the analysis.
